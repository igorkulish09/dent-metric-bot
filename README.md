# Dent Metric v3

Telegram CRM для PDR-майстра.

## Головна зміна v3 — ручний калькулятор вм'ятини

Після вибору автомобіля, елемента, технології, складності та матеріалу бот отримує **базову ціну** з прайсу.

Далі майстер проходить фактори:

1. Вм'ятина з царапиною / без царапини
2. З маленьким сколом
3. Вм'ятина над жорсткістю
4. Обрисувало жорсткість
5. Повело геометрію
6. Лопнув метал чи ні
7. Вм'ятина на ребрі
8. Поганий доступ
9. Рятуємо деталь від заміни
10. Переробка після другого майстра ×3
11. Обов'язковий розбір або зняття деталі
12. Жорстка розтяжка

Для **кожного вибраного фактора** майстер сам вводить доплату в гривнях.

Наприклад:

```text
База                         1500 грн
Царапина                      +500 грн
Маленький скол                +300 грн
Повело геометрію            +1000 грн
Вм'ятина на ребрі             +500 грн
Поганий доступ                +800 грн
------------------------------------
Разом                        4600 грн
```

Якщо фактор не застосовується — майстер просто його не натискає.

Якщо доплата за вибраний фактор дорівнює нулю — можна ввести `0`.

## Дані зберігаються окремо

Кожна доплата зберігається в таблиці `dent_factors` із назвою фактора та сумою. Це дозволяє в майбутньому робити статистику: скільки разів застосовували поганий доступ, геометрію, ребро тощо.

## Базовий прайс

`💰 Ціни` — адміністратор може змінювати базову ціну для комбінації:

- елемент;
- технологія;
- складність;
- матеріал;
- клас авто.

Базова ціна не змінює доплати конкретної вм'ятини.

## Замовлення

Сценарій:

`Нове замовлення → замовник → марка → модель → номер → клас → фото → розмір → елемент → технологія → складність → матеріал → фактори → ціна вм'ятини → наступна вм'ятина → завершення.`

Можна додати необмежену кількість вм'ятин.

Для кожної вм'ятини зберігаються:

- фото;
- розмір;
- елемент;
- технологія;
- складність;
- матеріал;
- базова ціна;
- загальна ціна;
- всі вибрані фактори та їх доплати.

## Запуск через Docker

1. Створіть Telegram-бота через BotFather.
2. Скопіюйте `.env.example` у `.env`.
3. Вставте токен:

```env
BOT_TOKEN=ваш_токен
```

4. Вкажіть Telegram ID адміністратора:

```env
ADMIN_IDS=123456789
```

Для кількох адміністраторів:

```env
ADMIN_IDS=123456789,987654321
```

5. Запустіть:

```bash
docker compose up -d --build
```

6. Перевірте:

```bash
docker compose logs -f bot
```

7. У Telegram відкрийте бота та натисніть `/start`.

## Локальний запуск

Потрібні Python 3.12+ та PostgreSQL.

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
python -m app.main
```

Windows:

```powershell
.venv\Scripts\activate
copy .env.example .env
python -m app.main
```

## Важливо для production

Це MVP. Перед бойовим запуском бажано додати Alembic migrations, резервне копіювання БД, webhook, журнал дій, ролі майстер/адміністратор, редагування вже створених факторів і повноцінне погодинне планування.

## Календар — фінальні зміни v3.1

- 🟢 вільні робочі дні;
- 🔴 зайняті дні;
- ⚪ неділі як вихідні;
- перемикання місяців кнопками `‹` / `›`;
- натискання на зайнятий день показує замовлення;
- зайняті дні недоступні під час нового бронювання;
- бронювання на кілька днів автоматично пропускає неділі;
- перед збереженням перевіряються всі дні бронювання на конфлікти.

У Telegram немає справжнього кольорового фону клітинки календаря, тому кольорова індикація реалізована емодзі.
